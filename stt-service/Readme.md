# Локальный STT-сервис на Vosk

Изолированный HTTP-сервис для распознавания русской речи. Сервис принимает
только WAV с параметрами 16 кГц, моно, 16-битный PCM и возвращает распознанный
текст.

Используемая модель: `vosk-model-small-ru-0.22`.

Модель скачивается и распаковывается во время сборки Docker-образа. После
сборки контейнер не обращается к интернету и не требует внешних API или ключей.

Принятое решение: Vosk выполняется в отдельном рабочем потоке, а загруженное аудио читается порциями и после 1 МиБ автоматически переносится из памяти во временный файл на диске.

## Ограничения

- Максимальный размер файла: 20 МиБ.
- Максимальная длительность: 180 секунд.
- Только WAV.
- Частота дискретизации: 16000 Гц.
- Один канал.
- 16-битный несжатый PCM.
- Язык распознавания всегда русский.
- Серверная конвертация аудио не выполняется.
- `ffmpeg` в образе отсутствует.

## Сборка

Из каталога `stt-service`:

```bash
docker build -t local-vosk-stt .
```

Во время этой команды Docker один раз скачает
`vosk-model-small-ru-0.22`. Для сборки интернет нужен, для запуска готового
образа — нет.

## Запуск

```bash
docker run --rm \
  --name local-vosk-stt \
  -p 8200:8200 \
  local-vosk-stt
```

## Проверка готовности

```bash
curl -i http://localhost:8200/health
```

Успешный ответ:

```json
{
  "status": "ok",
  "model_loaded": true
}
```

Если модель отсутствует или повреждена:

```json
{
  "status": "unavailable",
  "model_loaded": false
}
```

HTTP-статус в этом случае будет `503`.

## Распознавание файла

```bash
curl -i \
  -X POST \
  -F "audio=@test.wav;type=audio/wav" \
  http://localhost:8200/stt
```

Пример ответа:

```json
{
  "text": "подготовить служебную записку до пятнадцатого сентября",
  "duration_seconds": 4.82,
  "model": "vosk-model-small-ru-0.22"
}
```

Расширение файла и переданный клиентом MIME-тип не считаются доказательством
формата. Сервис проверяет фактический WAV-заголовок и параметры аудио.

## Автоматическая техническая проверка

Сначала запустите контейнер, затем из каталога `stt-service` выполните:

```bash
python3 test_manual.py
```

Скрипт использует только стандартную библиотеку Python. Он:

1. проверяет `/health`;
2. создаёт односекундный WAV с тишиной;
3. отправляет его полем `audio` на `/stt`;
4. проверяет HTTP-статус и структуру JSON.

Для синтетического звука поле `text` обычно будет пустой строкой — это
нормально.

Другой адрес можно передать явно:

```bash
python3 test_manual.py --url http://127.0.0.1:8200
```

## Фрагмент docker-compose.yml

Путь `./stt-service` считается относительно файла `docker-compose.yml`
основного проекта.

```yaml
services:
  stt_service:
    build:
      context: ./stt-service
    ports:
      - "8200:8200"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8200/health"]
      interval: 10s
      timeout: 5s
      retries: 6
      start_period: 15s
```

Запуск только этого сервиса:

```bash
docker compose up --build stt_service
```

## Ручная проверка голосом

Если исходная запись сделана не в требуемом формате, для локальной проверки
её можно заранее преобразовать установленным на компьютере `ffmpeg`:

```bash
ffmpeg -i input.mp3 \
  -ar 16000 \
  -ac 1 \
  -sample_fmt s16 \
  test.wav
```

`ffmpeg` используется только разработчиком для подготовки тестового файла. Он
не входит в сервис и не нужен в продакшене.

Отправка подготовленного файла:

```bash
curl -sS \
  -F "audio=@test.wav;type=audio/wav" \
  http://localhost:8200/stt
```

## Поведение при ошибках

Некорректный или повреждённый файл:

```json
{
  "detail": "файл не является корректным WAV"
}
```

HTTP-статус: `422`.

Запись длиннее 180 секунд:

```json
{
  "detail": "запись длиннее 3 минут, разбейте на части"
}
```

HTTP-статус: `422`.

Файл больше 20 МиБ:

```json
{
  "detail": "файл слишком большой"
}
```

HTTP-статус: `413`.

Модель не загрузилась:

```json
{
  "detail": "сервис распознавания временно недоступен"
}
```

HTTP-статус: `503`.
