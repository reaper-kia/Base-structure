# Локальный RAG

RAG помогает модели выбирать официально-деловую терминологию и структуру
фраз. Он не является реестром фактов и не заполняет реквизиты сведениями,
которых нет в черновике. Поэтому HTTP-контракт между бэкендом и
`ml_service` не изменён.

## Поток запроса

1. Из типа, подсказки по структуре и первых символов черновика собирается
   поисковый запрос.
2. Файлы `.md` и `.txt` из `ml_service/knowledge/` детерминированно
   нарезаются на фрагменты. Путь, позиция и SHA-256 содержимого сохраняются
   в метаданных индекса.
3. `bge-m3` строит embeddings пакетно через актуальный endpoint Ollama
   `POST /api/embed`. Результаты ранжируются по cosine similarity.
4. Если Ollama или embedding-модель недоступны, запрос автоматически
   переходит на лексическое ранжирование. Основная обработка не падает.
5. Не более `RAG_TOP_K` фрагментов и `RAG_MAX_CONTEXT_CHARS` символов
   помещаются в отдельный изолированный блок промпта.
6. Ответ проходит обычные schema validation и Fact Guard.

Индекс хранится в памяти процесса и обновляется, когда меняются размер или
время модификации справочных файлов. После временного отказа vector search
повторно проверяется через минуту.

## Добавление материалов

Положите UTF-8 файл `.md` или `.txt` в `ml_service/knowledge/`. Заголовки
Markdown становятся названиями разделов. Используйте материалы о стиле,
терминах и структуре документов; не добавляйте команды для модели и не
рассчитывайте на справочник как на источник реквизитов.

После изменения корпуса увеличьте `PROMPT_VERSION` в `.env`: ответы
бэкенда кэшируются по версии промпта, а уже сохранённый ответ не должен
пережить обновление базы знаний. В локальном Compose каталог подключён
read-only и подхватывается без пересборки; в production он копируется в
образ, поэтому образ нужно пересобрать.

## Настройки

| Переменная | По умолчанию в Compose | Назначение |
|---|---:|---|
| `RAG_ENABLED` | `true` | включает retrieval перед генерацией |
| `RAG_VECTOR_ENABLED` | `true` | разрешает embeddings; `false` оставляет lexical mode |
| `RAG_EMBED_MODEL` | `bge-m3` | модель Ollama для multilingual embeddings |
| `RAG_EMBED_TIMEOUT_SECONDS` | `15` | таймаут одного embedding-запроса |
| `RAG_EMBED_KEEP_ALIVE` | `0` | выгружает embedding-модель перед 7B-генерацией |
| `RAG_TOP_K` | `3` | максимум фрагментов |
| `RAG_MIN_SCORE` | `0.2` | нижняя граница vector similarity |
| `RAG_MAX_CONTEXT_CHARS` | `3000` | общий лимит RAG-блока промпта |
| `RAG_KNOWLEDGE_DIR` | `/app/knowledge` | каталог справочников в контейнере |

## Проверка

```bash
make pull-model
curl localhost:8100/health/rag
make ml-test
```

После первого обработанного документа `last_method` показывает `vector`
или `lexical`. Поле `last_error` объясняет переход в fallback; сам
`/health` остаётся успешным, потому что RAG — необязательное обогащение.
