# Как добавить тип документа или шаблон

Тип документа определяет **содержание**: структуру и набор обязательных
реквизитов. Шаблон определяет **оформление**: поля, шрифты, интервалы,
колонтитулы, расположение блоков. Это независимые сущности — любой тип
можно оформить любым шаблоном.

---

## Новый тип документа

Один файл: `src/modules/documents/config/doc_types/<id>.yaml`.

```yaml
name: "Приказ"
description: "Распорядительный документ по основной деятельности"
structure_hint: "заголовок -> констатирующая часть -> распорядительная часть -> подпись"

# Печатать ли «ПРИКАЗ» отдельной строкой над заголовком.
show_type_title: true

requisites:
  - {key: subject, label: "Заголовок", required: true}
  - {key: doc_date, label: "Дата документа", required: true}
  - {key: reg_number, label: "Номер приказа", required: true}
  - {key: author, label: "Подписант: должность, ФИО", required: true}
  - {key: position, label: "Должность подписанта", required: true}
  - {key: signature, label: "Подпись", required: true}
  - {key: executor, label: "Исполнитель и телефон", required: false}

auto_fillable:
  doc_date: today
```

Дальше:

1. Добавить `"приказ"` в `_DOC_TYPE_ORDER` в
   `application/services/doc_type_registry.py` — этим задаётся порядок
   карточек в интерфейсе.
2. Добавить значение в `DocType` в `domain/enums.py`.
3. Дописать строку в таблицу `contracts/api.md` — иначе
   `python scripts/check_doc_types_table.py` упадёт.

**Ключи реквизитов лучше брать из существующего словаря**
(`addressee`, `author`, `position`, `doc_date`, `reg_number`, `subject`,
`signature`, `salutation`, `executor`): под них уже есть места во всех
шаблонах. Новый ключ потребует правки раскладки каждого шаблона, иначе
загрузчик объявит шаблон недоступным — см. «проверка покрытия» ниже.

Ни бэкенд, ни `ml_service`, ни рендерер править не нужно: список ключей
уходит в модель прямо из этого YAML.

### Что можно автозаполнять

`auto_fillable` — единственная легальная лазейка. Разрешено только то,
что система знает достоверно: правило `today` подставляет текущую дату
формирования документа.

Содержательные даты, суммы, фамилии и номера автозаполнять нельзя. Если
реквизита нет, он уходит со статусом `missing`, интерфейс просит его
заполнить, а в документе остаётся явная пометка `[Метка]`.

## Новый шаблон оформления

### Вариант 1: загрузить свой DOCX

В интерфейсе — кнопка загрузки шаблона; в API —
`POST /api/templates/upload`.

Из файла вычитываются поля страницы, гарнитура, кегль, интервал, красная
строка, выравнивание и тексты колонтитулов. Плейсхолдеры вида
`[Название организации]` превращаются в токены подстановки.

Расположение реквизитов из DOCX вывести нельзя — в файле лежат абзацы, а
не смысл. Берётся раскладка классического шаблона; поправить её можно в
`rules.yaml` созданной папки. Всё, что не удалось вычитать, перечисляется
в `warnings` ответа.

### Вариант 2: собрать папку руками

`src/modules/templates/assets/<id>/`:

```
rules.yaml       — правила оформления
template.docx    — базовый файл (стили, колонтитулы); необязателен
```

Минимальный `rules.yaml`:

```yaml
name: "Мой шаблон"

page: {top_mm: 20, bottom_mm: 20, left_mm: 30, right_mm: 15}
font: {family: "Times New Roman", size_pt: 14}
spacing: {line: 1.5, first_line_indent_cm: 1.25, space_after_pt: 0}
alignment: justify

header_footer:
  header: {text: "{org_name}", font_size_pt: 11}
  footer: {text: "Страница {page}", font_size_pt: 11}

requisites_layout:
  - {key: addressee, position: top_right}
  - {key: author, position: top_right}
  - key: date_number
    type: line
    position: top_left
    parts:
      - {label: "Дата:", key: doc_date}
      - {label: "Номер:", key: reg_number}
  - {key: doc_title, type: doc_title, position: center, bold: true}
  - {key: subject, position: center, bold: true}
  - {key: salutation, position: left}
  - {key: body, position: body}
  - key: signature_block
    type: signature
    position: bottom_left
    keys: [position, signature]
  - {key: executor, position: bottom_left, font_size_pt: 10}
```

Без `template.docx` добавьте `base_docx: none` — это легальный режим
«шаблон только из правил».

Полное описание формата — `contracts/template_format.md`.

### Проверка покрытия

Загрузчик сверяет обязательные реквизиты **всех** типов документов с
ключами, которые встречаются в раскладке, включая вложенные `parts[].key`,
`rows[].value_key` и `keys[]`.

Если обязательному реквизиту негде оказаться, шаблон помечается
`available: false` **при загрузке**, а не молча теряет данные при
генерации. В карточке он показывается неактивным, в логе — причина.

### Проверить результат

```bash
make docx-samples     # 8 файлов в artifacts/: 4 типа x 2 шаблона
make test             # матрица «каждый обязательный реквизит доехал до файла»
```

Тесты в `tests/unit/template/` прогоняют каждый тип документа через
каждый шаблон и проверяют, что ни один обязательный реквизит не потерялся,
поля и шрифты совпадают с правилами, а незаполненные реквизиты помечены
явно.

## Название организации

Верхний колонтитул классического шаблона — это название организации, и
оно одно на всю установку, поэтому живёт в настройке `ORG_NAME`, а не в
реквизитах документа.

```bash
ORG_NAME=ООО «Ромашка»
```

Пока настройка не заполнена, в колонтитуле остаётся
`[Название организации]` — та же явная пометка незаполненного поля, что и
у реквизитов. Своё название сервис не выдумывает.
