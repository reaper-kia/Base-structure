Основание — официальные материалы организаторов, лежат в

- `шаблоны/Описание шаблонов оформления.docx`

  `шаблоны/Шаблон__Современный регламентный.docx` — те же файлы уже

  должен дописывать содержимое в них, а не собирать документ с нуля)
- `Примеры/*.docx` — заполненные образцы по каждому типу и шаблону classic
- `Черновики/<тип>/*.txt` — по 4 черновика на тип (16 всего), пригодны как

Этот документ уточняет ранее подготовленные контракты и TL-tasks.
При расхождении требований приоритет имеют материалы организаторов.
Актуальные ключи и обязательность реквизитов хранятся в
`src/modules/documents/config/doc_types/*.yaml`.

## Реквизиты

Подсчёт — по факту в `ПЕРЕЧЕНЬ ОБЯЗАТЕЛЬНЫХ РЕКВИЗИТОВ...docx`, без учёта
«Текст» (он не реквизит, хранится отдельно в `improved_text`):

- memo и report: 8 полей, из них 7 обязательных.
- reference: **5 полей, из них 4 обязательных** (исправлено — было
  ошибочно указано 6/5, см. «Что было неверно» ниже).
- letter: 9 полей, из них 7 обязательных.
- Основной текст обязателен и хранится отдельно в `improved_text`.
- signature содержит сведения для блока подписи из черновика
  или от пользователя. Автоматически выдумывать подписанта нельзя.
- Для reference отдельного поля «должность составителя» **нет** — формат
  реквизита «Составитель» уже включает и должность, и ФИО одной строкой
  (организаторы: «Составитель — ... Формат: должность, ФИО»). Не заводить
  под это отдельный `position` для reference — только для memo/report/letter,
  где организаторы явно выделяют «Должность» отдельной строкой.
- Для письма author должен сохранять организацию отправителя.
- Недостающие заголовок и тему запрашиваем или обозначаем незаполненными.
- Факты из примеров DOCX не переносим в пользовательский документ.

### Что было неверно и исправлено 2026-09-11

`reference.yaml` содержал лишнее обязательное поле `position` («Должность
составителя»), которого нет в официальном перечне организаторов — там
должность составителя указана как часть формата поля «Составитель», а не
отдельным реквизитом (в отличие от memo/report/letter, где «Должность»
организаторами прямо выделена отдельной строкой). Поле удалено из
`config/doc_types/reference.yaml`. Эта же ошибка была и в предыдущей версии
этого файла (написано «6 полей, 5 обязательных» и «должность составителя
хранится отдельно в position») — тоже исправлено.

## Автозаполнение

Организаторы разрешают текущую дату документа и порядковый номер.
На текущем этапе реализовано только правило `doc_date: today`.
Отсутствующий номер запрашивается или обозначается незаполненным.
Номер из исходного текста сохраняется без замены.
Даты событий не используются автоматически как дата документа.

## Оформление

Точные параметры — из `Описание шаблонов оформления.docx`. По состоянию на
2026-09-12 `src/modules/templates/assets/{classic,modern}/rules.yaml`
приведены в соответствие обоим разделам целиком.

### classic — «Классический корпоративный»

| Параметр | Значение | Реализовано |
|---|---|---|
| Поля страницы | лево 30мм, право 15мм, верх 20мм, низ 20мм | да |
| Шрифт | Times New Roman, 14pt | да |
| Интервал / отступ | 1.5, красная строка 1.25см | да |
| Выравнивание текста | по ширине | да |
| Реквизиты | адресат справа; дата и номер сверху одной строкой; заголовок по центру, полужирный; подпись слева | да |
| Верхний колонтитул | название организации | да, из настройки `ORG_NAME` |
| Нижний колонтитул | номер страницы, TNR 11pt по центру | да, настоящее поле `PAGE` |

### modern — «Современный регламентный»

| Параметр | Значение | Реализовано |
|---|---|---|
| Поля страницы | лево 25мм, право 20мм, верх 15мм, низ 15мм | да |
| Шрифт | Arial, 12pt | да |
| Интервал / отступ | 1.15, без красной строки | да |
| Выравнивание текста | по левому краю | да |
| Реквизиты | тема сверху слева, полужирная; блок «Кому / От кого» — таблица; подпись по центру | да |
| Верхний колонтитул | отсутствует | да, пустой `header.text` |
| Нижний колонтитул | название документа и дата, Arial 10pt по центру | да, `{subject} \| {doc_date}` |

Про нижний колонтитул modern: организаторы пишут «название документа и
дата», в самом шаблоне стоит `[Название документа] | [Дата]`. Подставляется
заголовок конкретного документа (`subject`), а не название типа: для справки
и письма именно заголовок отвечает на вопрос «что это за документ».

### Название типа документа отдельной строкой

В эталонных примерах служебная записка, докладная записка и информационная
справка начинаются со строки «СЛУЖЕБНАЯ ЗАПИСКА» над заголовком, а письмо —
сразу с темы. Это свойство типа, а не шаблона, поэтому им управляет
`show_type_title` в `doc_types/<id>.yaml`, а печатает блок
`{type: doc_title}` в раскладке шаблона.

### Что исправлено 2026-09-12

- `classic`: верхний колонтитул был пустой — добавлено название организации
  из настройки `ORG_NAME` (по умолчанию — явная пометка незаполненного поля).
- `classic`: в нижнем колонтитуле печаталось **два** номера страницы. Поле
  `PAGE` образца лежит внутри элемента управления содержимым, и очистка по
  списку параграфов его не удаляла. Теперь колонтитул чистится целиком.
- Дата и номер печатались двумя отдельными абзацами вместо одной строки
  «Дата: … Номер: …», как в образцах.
- Блок подписи печатал должность, автора и фамилию тремя строками подряд,
  дублируя содержание. Приведён к формату организаторов: должность, линия
  подписи, И.О. Фамилия.
- Добавлена строка с названием типа документа (см. выше).

Оформление не отменяет обязательность реквизитов выбранного типа.
