# Документ за 3 шага

ИИ-конструктор служебных документов: черновой текст на входе — готовый
редактируемый DOCX на выходе.

Пользователь вставляет черновик, выбирает тип документа и шаблон
оформления, получает файл. Между этими шагами система исправляет
орфографию и стиль, приводит текст к официально-деловому виду, извлекает
реквизиты, показывает недостающие и собирает документ по правилам
выбранного шаблона.

Ключевое ограничение продукта: **ИИ не имеет права добавить ни одного
факта, которого не было в черновике**. За этим следит не промпт, а
детерминированный код — Fact Guard.

---

## Быстрый старт

Нужен только Docker с плагином Compose.

```bash
cp .env.example .env
docker compose up -d --build
make pull-model            # один раз: ~6 ГБ весов двух моделей
```

Интерфейс — http://localhost:3000, API — http://localhost:8000/docs.

Проверить, что всё поднялось:

```bash
make models                # веса на месте
curl localhost:8000/api/dev/state
make smoke                 # сквозной сценарий: черновик -> DOCX
```

Первая обработка на CPU занимает 20–60 секунд: это локальная 7B-модель,
а не облачный API.

### Что нужно от машины

| Ресурс | Минимум | Почему |
|---|---|---|
| RAM | 8 ГБ | 6 ГБ отданы контейнеру с моделью |
| Диск | 20 ГБ | ~6 ГБ веса, остальное — образы и база |
| CPU | 4 ядра | без GPU обработка идёт на процессоре |

GPU не требуется. Внешних платных API в решении нет: модель, распознавание
речи и генерация DOCX работают локально, ключей доступа подключать не надо.

### Боевой стенд

```bash
cp .env.example .env.prod    # заполнить пароли и ORG_NAME
docker compose -f compose.prod.yml up -d --build
```

Автоматический деплой на VPS — `infra/ansible/README.md`.

## Стек и почему он такой

| Слой | Технология | Обоснование |
|---|---|---|
| Backend | FastAPI, Python 3.12 | асинхронные фоновые задачи и валидация схем из коробки |
| Хранение | PostgreSQL + SQLAlchemy | статус обработки переживает перезапуск; задание допускает in-memory, но тогда документ теряется вместе с процессом |
| Кэш | Redis | повторная обработка того же черновика не тратит минуту на модель |
| ИИ | Ollama + `qwen2.5:7b-instruct`, `bge-m3` | локальная генерация и multilingual embeddings без чужих ключей и лимитов |
| DOCX | python-docx | оформление собирается программно по правилам, а не моделью |
| Речь | Vosk, модель `small-ru` | голосовой ввод черновика без внешних сервисов |
| Frontend | React 19, TypeScript, Vite | — |
| Бот | MAX Bot API | второй канал того же сценария |

## Архитектура

```
                       ┌──────────────┐
   браузер  ──────────▶│   frontend   │  nginx: SPA + прокси
                       └──────┬───────┘
   MAX-бот  ─────────────┐    │
                         ▼    ▼
                  ┌──────────────────┐      ┌──────────────┐
                  │   backend (app)  │─────▶│  stt_service │  Vosk
                  │                  │      └──────────────┘
                  │  documents ──────┼────▶ ┌──────────────┐   ┌────────┐
                  │  templates       │      │  ml_service  │──▶│ ollama │
                  └────────┬─────────┘      └──────────────┘   └────────┘
                           │
                   ┌───────┴────────┐
                   │  Postgres  Redis│
                   └────────────────┘
```

Границы модулей выбраны по одному принципу: **содержание отдельно от
оформления**.

- `src/modules/documents` — черновик, реквизиты, статусы, оркестрация
  пайплайна. Ничего не знает про шрифты и поля страницы.
- `src/modules/templates` — правила оформления и сборка DOCX. Ничего не
  знает про модель: в рендерере физически нет импорта ИИ-клиента, и это
  проверяется тестом.
- `ml_service` — отдельный контейнер с собственным HTTP-контрактом.
  Заменить Ollama на другой API — правка внутри него, бэкенд не трогается.

Почему ИИ вынесен в отдельный процесс, а не в бэкенд: так границу видно, а
не приходится объяснять словами, и сценарий 6 показывается одной командой
`docker compose stop ml_service` — бэкенд жив, черновик цел, сообщение
понятное.

Подробности: `docs/architecture.md`.

## Пайплайн обработки

```
черновик
   │
   ├─▶ кэш по хэшу (черновик + тип + версия промпта)
   │
   ├─▶ ml_service ──▶ RAG по локальным справочникам
   │                └▶ Ollama, ответ по строгой JSON-схеме
   │                    ├─ не разобрался  → починка регуляркой
   │                    ├─ всё ещё нет    → repair-проход моделью
   │                    └─ всё ещё нет    → резервная обработка правилами
   │
   ├─▶ Fact Guard: сверка якорей черновика и результата
   │        clean / warning / blocked
   │
   ├─▶ валидация реквизитов по типу документа
   │        found_in_draft / auto_filled / missing
   │
   └─▶ рендер DOCX по правилам выбранного шаблона
```

Статусы документа: `processing` → `processed`, `degraded` (сработала
резервная обработка) или `failed`. Черновик не перезаписывается никогда.

Логика работы с ИИ, промпт и защита от галлюцинаций разобраны в
`docs/ai-logic.md`, машиночитаемый контракт — в
`contracts/llm_contract.md`.

## Реквизиты

Набор задаёт тип документа, оформление — шаблон. Это независимые сущности:
смена шаблона не меняет ни слова, смена типа не меняет ни одного шрифта.

| Тип | Обязательные | Необязательные |
|---|---|---|
| Служебная записка | адресат, автор, должность, дата, номер, заголовок, подпись | исполнитель |
| Докладная записка | адресат, автор, должность, дата, номер, заголовок, подпись | исполнитель |
| Информационная справка | заголовок, дата, составитель, подпись | адресат |
| Письмо | адресат, отправитель, должность, дата, номер, тема, подпись | обращение, исполнитель |

Что можно заполнить автоматически:

- **дата документа** — текущая дата, это единственное, что система знает
  достоверно;
- **всё остальное — нельзя.** Отсутствующий реквизит либо запрашивается у
  пользователя, либо остаётся в документе явной пометкой `[Адресат]`,
  выделенной жёлтым. Содержательные даты, суммы, фамилии и номера система
  не придумывает.

Если пользователь осознанно оставил поле пустым, повторная обработка это
решение не перезатирает.

## Переменные окружения

Полный список с комментариями — `.env.example`. Обязательно посмотреть:

| Переменная | Значение по умолчанию | Что делает |
|---|---|---|
| `ORG_NAME` | `[Название организации]` | название в верхнем колонтитуле классического шаблона. Пока не заполнено — в документе остаётся явная пометка |
| `ML_SERVICE_URL` | `http://ml_service:8100` | пустая строка выключает ИИ: бэкенд обязан это пережить |
| `AI_FORCE_FAILURE` | `false` | имитация отказа ИИ для демонстрации |
| `RAG_ENABLED` | `true` | добавить в промпт релевантные правила терминологии и стиля |
| `RAG_VECTOR_ENABLED` | `true` | vector search через `bge-m3`; при отказе остаётся lexical fallback |
| `PROCESSING_DEADLINE_SECONDS` | `180` | после этого документ уходит в `failed` с понятным сообщением |
| `USER_TEMPLATES_DIR` | `data/templates` | куда складываются загруженные шаблоны |
| `CACHE_TTL_SECONDS` | `600` | кэш результатов обработки |

Ключей внешних сервисов подключать не нужно — их нет.

## Демонстрационные данные

`data/demo-drafts/` — 16 черновиков организаторов, по четыре на каждый тип
документа: аккуратный, с ошибками и просторечиями, без обязательного
реквизита и в свободной форме. Те же файлы стоят кнопками на экране ввода
и используются в тестах — один источник, чтобы демо и проверки не
разъезжались.

`artifacts/` — восемь эталонных DOCX (4 типа × 2 шаблона), пересобираются
командой `make docx-samples`.

`docs/organizer-materials/` — исходный стартовый пакет как есть.

## Проверка решения

```bash
make test        # тесты бэкенда
make lint
make ml-test     # тесты ИИ-слоя
make ml-gate     # доля валидных ответов модели на 21 черновике
make smoke       # сквозной сценарий до скачивания DOCX
cd frontend && npm ci && npm run test && npm run build
```

Независимо проверить внутреннюю логику можно, не залезая в код:

- `GET /api/trace/{id}` — что ушло в модель, что вернулось, что решил Fact
  Guard, что решил валидатор, сколько заняла каждая стадия;
- `GET /api/dev/state` — поднята ли модель, какие шаблоны подхватились;
- `POST /api/dev/break-ai` — включить имитацию отказа ИИ;
- `/dev` в интерфейсе — то же самое кнопками.

Полное описание API с примерами — `contracts/api.md`.

## Как расширять

- **Новый тип документа** — один YAML в
  `src/modules/documents/config/doc_types/`. Ни бэкенд, ни ИИ-сервис,
  ни рендерер не трогаются.
- **Новый шаблон оформления** — папка в
  `src/modules/templates/assets/<id>/` с `rules.yaml` и базовым `.docx`,
  либо загрузка своего DOCX через интерфейс.
- **Другая модель** — `OLLAMA_MODEL` в окружении; другой провайдер ИИ —
  правка одного файла в `ml_service`.
- **Новый справочник RAG** — `.md` или `.txt` в `ml_service/knowledge/`;
  после изменения увеличьте `PROMPT_VERSION`, чтобы сбросить кэш ответов.

Пошагово: `docs/adding-template.md`; устройство RAG: `docs/rag.md`.

## Что реализовано и чего нет

Реализовано сверх обязательного минимума: предпросмотр и ручная правка
улучшенного текста, сравнение «было / стало», голосовой ввод черновика,
загрузка и автоматический разбор произвольного DOCX-шаблона, бот в
мессенджере MAX, журнал обработки, dev-панель.

Известные ограничения — `docs/limitations.md`.
